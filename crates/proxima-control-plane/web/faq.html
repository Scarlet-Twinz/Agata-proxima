Understand Proxima before you deploy it.

A practical explanation for developers, architects, security teams and people encountering tenant isolation for the first time.

What problem does Agata Proxima solve?

Multi-tenant applications often rely on application code to remember which tenant may access which data. Proxima moves a significant part of that responsibility toward an infrastructure boundary, where tenant identity and database access can be enforced and independently verified.

Is Proxima a database?

No. PostgreSQL remains the database. Proxima Engine sits in the data path and controls how tenant-scoped sessions reach the upstream database. PostgreSQL roles and Row Level Security provide an additional database-side boundary.

Does every application need to become a Proxima application?

No. The goal is to keep application code focused on product behavior while the infrastructure layer handles the mechanics of tenant context, session routing and enforcement.

What happens if Proxima Cloud goes down?

The control plane is deliberately non-authoritative. An already-running Engine remains responsible for the data-plane enforcement path. Management availability must not become permission to weaken tenant isolation.

What does Proxima Verify actually test?

Verification can exercise valid tenant sessions, invalid and expired identity material, tampered signatures, cross-tenant SELECT/INSERT/UPDATE/DELETE attempts, prepared statements, transaction behavior, upstream failures, PostgreSQL RLS and recovery behavior.

Why have both Engine enforcement and PostgreSQL RLS?

Defense in depth. The Engine provides the runtime routing and session boundary, while PostgreSQL independently enforces policies at the database layer. A security-sensitive system should not rely on one layer when two independently testable boundaries are possible.

Can beginners use Proxima?

Yes, but beginners should understand the model before deploying it. Start with the platform and security pages, create a workspace, then use the dashboard to understand tenants, policies, fleet state and verification evidence. Production deployment still requires proper secrets, TLS, backups, monitoring and external validation.

Is the dashboard itself the security boundary?

No. The dashboard is an operational interface. The Proxima Engine and the database security model remain the enforcement layers. The UI should make those boundaries visible rather than pretending that a green badge creates security.

Where does Stripe fit?

Stripe handles production billing events and hosted billing flows. Proxima's control plane translates the resulting billing state into server-side entitlements. The interface should never be the authority for whether a capability is allowed.

Where does enterprise SSO fit?

Microsoft Entra can provide enterprise identity. The control plane validates issuer, tenant, audience, signatures and nonce/state requirements before establishing an Agata session.

What should I deploy first?

Start with the Engine and PostgreSQL boundary, then enroll it into the control plane. Before calling a production rollout complete, validate HTTPS, production PostgreSQL, external identity, billing, email delivery, backups/restores, monitoring and external tenant-isolation acceptance.
